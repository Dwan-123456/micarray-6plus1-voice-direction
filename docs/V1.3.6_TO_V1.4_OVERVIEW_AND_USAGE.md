# 6+1麦克风阵列：v1.3.6架构、v1.4方向与使用说明

本文供第一次接触项目的人快速了解系统用途、处理流程和Development Test UI的基本操作。

## 1. 系统要做什么

系统使用半径4 cm的6个圆周麦克风和1个中央麦克风，面向诊室中的多人对话：先判断声音来自哪个方向，再按方向增强和拼接音频，最后判断人声并用声纹归并同一讲话人。

程序采用**二维远场平面波假设**。声源位置只用方位角`theta`表示：`theta`是声源方向与阵列坐标系x轴正半轴的夹角，角度范围为`0～360°`。系统不估计距离和俯仰角，因此讲话人与阵列应尽量位于同一平面。

当前使用场景允许现场共有3名讲话人，但假设同一时刻最多2人讲话，且两个同时讲话方向的夹角不小于50°。需要特别区分：L2最多可以显示3条方向轨迹，但L4只处理单人或双人音频，不能分离3人同时讲话。

## 2. 版本定位

| 版本 | 定位 | 状态 |
|---|---|---|
| `v1.3.6` | 完整的L1～L6链路，可对双人混合讲话进行方向增强、双人分离、人声检测和匿名声纹归并 | 已发布 |
| `1.4` | 重点保留L1、L2，形成轻量、实时、稳定的1～3个声源方向定位程序 | 开发目标，尚未完全落地 |

当前1.4开发分支仍保留v1.3.6的完整L1～L6代码。“只保留L1、L2”是后续开发方向，不代表当前代码已经删除L3～L6。

## 3. 整体架构

```text
6+1麦克风阵列音频
    ↓
L1  IMCRA底噪估计 → 每20 ms声源概率p
    ↓
L2  Gate → Norm-MUSIC方向定位 → IMM-JPDA方向ID跟踪与预测
    ↓                         └── 输出：方位角theta + 方向track_id
L3  DS / MVDR / 按空间可分性选择LCMV或MVDR
    ↓
TrackAudioStreamHub：按track_id拼接连续方向音轨
    ↓
L4  单人旁路；双人使用MossFormer2将混合轨分为两条候选
    ↓
L5  NVIDIA MarbleNet CNN：每20 ms判断Voice / Non-Voice
    ↓
L6  CAMPPlus声纹 + 质量分数：跨音轨全局匹配并归为Speaker A、B……
```

各层的作用如下：

- **L1**：读取、校准并保存麦克风阵列音频；使用IMCRA持续估计环境底噪并输出每20 ms的声源概率`p`。
- **L2**：Gate先过滤无明显声源的窗口；随后在2000～4000 Hz运行加权frequency-normalized MUSIC，输出最多3个、两两至少相隔50°的方向；Circular IMM-JPDA负责保持方向ID并预测短时运动。
- **L3**：提供DS、Loaded MVDR和optimized三种模式。DS最快；Loaded MVDR稍慢但可实时；optimized会根据空间可分性选择LCMV或MVDR，双声源路径计算较重。
- **音频拼接**：L3之后由TrackAudioStreamHub按方向ID去重、补洞并拼成连续音轨，这不是L3波束形成算法本身的职责。
- **L4**：单人轨当前直接旁路；双人轨使用MossFormer2（或TIGER）估计两条匿名讲话音轨。输出是算法估计结果，不能理解为无失真的“原始声音”。
- **L5**：使用未经项目微调的NVIDIA多语言MarbleNet模型判断每个20 ms片段是否为人声，不进行语音转写。当前观察中英文人声检测优于中文，中文诊室数据仍需专项验证。
- **L6**：从人声片段提取CAMPPlus声纹，结合音频质量分数做跨轨匹配和聚类；结果是匿名的Speaker A、B等，不是现实人物身份。

### 参数口径

- v1.3.6代码默认：L1在`250～3400 Hz`按三个频带聚合概率；L2 Gate默认`p ≥ 0.60`。
- 1.4计划/实验口径：L1改用`300～1500 Hz`加权概率，L2使用`p ≥ 0.80`的严格Gate。该口径尚未完整写入当前代码。

## 4. 当前状态与限制

- 根据操作者提供的测试观察，L1和L2已连续运行约3小时，方向定位总体实时、稳定且较准确；但该结果仍需保存配置和日志后才能作为正式验收证据。
- 测试中观察到进程专用内存约每分钟增加1.7 MB，原因仍待定位。
- L3的DS和Loaded MVDR可以实时运行；optimized空间可分性路径较慢，可能影响整链输出速度。
- 4 cm阵列对低频缺少足够空间差异，约80～1500 Hz的双声源分离效果较差。
- 近距离声源、明显不共面声源、夹角小于50°或三人同时讲话，均不属于当前可靠使用范围。

## 5. v1.3.6使用方法

在项目根目录启动Development Test UI：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\launch_dev_test_ui.ps1
```

### 只做方向定位（L1+L2）

1. 连接麦克风阵列并启动界面。
2. 点击“启动采集”。真实麦克风模式在正式录音开始前会保持L3/4/5关闭，L1和L2正常运行。
3. 在L2区域观察Gate、方向角和方向ID。
4. 点击“停止采集”结束。该流程可以重复运行。

### 运行完整L1～L6

1. 点击“启动采集”，等待L1和L2完成预热。
2. 点击**“正式录音开始”**。程序会重置本轮方向轨迹、自动开启L3/4/5，并开始保存正式音频。
3. 采集中可查看DOA、方向ID、L3音轨以及渐进的L4～L6预览。
4. 结束时先点击“正式录音暂停”，再点击“停止采集”。
5. 等待界面完成队列排空、音轨封存及L4～L6最终处理后再关闭程序。

界面上方的“录制 / 暂停 / 结束”是独立的scratch临时录音，不会启动完整L1～L6流程；完整流程必须使用“正式录音开始”。L6没有独立开关，会跟随完整处理链自动运行。

更详细的接口、配置和故障边界见[`COMPLETE_ARCHITECTURE_AND_USAGE.md`](COMPLETE_ARCHITECTURE_AND_USAGE.md)，所有实际默认参数以[`../config/config.yaml`](../config/config.yaml)为准。
