# 6+1麦克风阵列 v1.4.1：架构、使用说明与1小时长测报告

本文说明已发布版本`v1.4.1`的用途、处理流程、关键参数、Development Test UI使用方法，以及发布前完成的1小时真实麦克风长测结果。对应不可变Git标签为`v1.4.1`，发布提交为`4d730f9`。

## 1. 版本定位

v1.4.1是一个轻量实时声源方向定位版本，只保留真实麦克风输入、L1和L2：

- L1负责8通道音频采集、7个物理麦克风校准、IMCRA环境底噪估计和声源概率；
- L2使用概率Gate过滤无明显声源的窗口，再用Norm-MUSIC估计方向；
- Circular IMM-JPDA把连续窗口中的方向关联为`track_id`，并在短时无观测时继续预测；
- Development Test UI实时显示电平、概率、Gate、MUSIC响应、方向ID和性能状态。

v1.4.1不包含L3波束形成、L4双人分离、L5人声CNN、L6声纹聚类、正式录音和数据管理。这些完整旧功能保存在不可变标签`v1.3.6`。

## 2. 使用目的与基本模型

系统面向室内远场语音场景，使用半径4 cm的6个圆周麦克风和1个中央麦克风估计声源方向。设备还提供一路`HardwareMix`，所以主机输入共8通道。

程序采用二维远场平面波假设，只输出声源方向与阵列坐标系x轴正半轴之间的方位角`theta`，范围为`0～359°`。系统不估计声源距离和俯仰角，因此声源应尽量与阵列处于同一平面。

公开MUSIC结果最多包含3个方向，默认有效阶数为2；候选方向之间至少相隔50°。这些方向ID描述空间轨迹，不等同于现实人物身份。

## 3. 完整架构图

```text
Sipeed MA-USB8真实输入
    输入：48 kHz、PCM S16_LE、8通道、每块960 sample（20 ms）
    ↓
AudioCapture / LiveSipeedSource
    ├── 有界采集交接队列
    ├── sequence_id与单调时间戳
    └── 输出：逻辑8通道float32音频
    ↓
ChannelCalibrator
    ├── 7物理麦增益、极性和整数延迟校准
    ├── HardwareMix只保留，不参与空间计算
    └── 输出：MIC0..MIC5、Center、HardwareMix
    ↓
IngestCoordinator
    ├── 建立session_id、stream_epoch和绝对sample时间轴
    ├── 发现断流、丢块或校准变化时重建epoch
    └── 输出：不可变IngestedAudioBlock
    ↓
L1 Layer1Imcra（每20 ms）
    ├── 7麦逐频噪声PSD与SPP
    ├── P1：每个物理麦的声源概率
    ├── P2：7个P1的中位数
    └── 可选IMCRA-Wiener预降噪
    ↓
WindowAssembler
    ├── 160 ms DecisionWindow
    ├── 每20 ms发布一次
    └── MUSIC使用其中最近200 ms滚动统计状态
    ↓
L2 Probability Gate
    ├── 输入：与当前窗口末端对齐的最新20 ms P2
    ├── P2 ≥ 0.80：OPEN
    └── P2 < 0.80：CLOSED，跳过完整MUSIC扫描
    ↓
Rolling frequency-normalized MUSIC
    ├── 7个校准物理麦
    ├── 2000～4000 Hz加权融合
    ├── 0～359°、1°步长扫描
    ├── 峰值筛选、50°圆周NMS
    └── 输出：360°SpatialResponse和最多3个候选方向
    ↓
Circular IMM-JPDA GlobalDirectionTracker
    ├── 静止/缓慢移动双模型预测
    ├── 圆周角度关联与联合概率数据关联
    ├── tentative → confirmed → coasting生命周期
    └── 输出：track_id、theta、观测/预测状态
    ↓
ApplicationRuntime / Development Test UI
    ├── 每20 ms持续发布最新时间轴结果
    ├── 过载时把MUSIC/ID实算周期降到40～200 ms
    ├── 未实算窗口复用最近结果，但更新时间戳
    └── 显示L1、L2、360°角度图、ID表和1秒性能统计
```

## 4. L1：采集、IMCRA和P2概率

### 4.1 输入与校准

| 参数 | v1.4.1值 |
|---|---:|
| 采样率 | 48 kHz |
| 设备通道数 | 8 |
| 每块长度 | 960 sample，即20 ms |
| 物理麦通道 | 7路：6个圆周麦 + Center |
| 阵列半径 | 0.04 m |
| HardwareMix | 保留为第8路，不参与IMCRA和MUSIC |
| 校准模型 | 增益 + 极性 + 整数sample延迟 |

校准后的公共通道顺序固定为`MIC0..MIC5、Center、HardwareMix`。输入出现sequence gap、时间戳异常、设备重启或采集交接丢块时，`IngestCoordinator`会建立新的`stream_epoch`，避免不同连续段共享旧状态。

### 4.2 IMCRA

| 参数 | v1.4.1值 |
|---|---:|
| 算法版本 | `cohen_imcra_2003_l1_v8` |
| 更新周期 | 20 ms |
| FFT长度 | 2048 |
| 分析窗 | periodic Hann |
| 预热时间 | 1 s |
| 输出频率范围 | 0～10000 Hz |
| P1/P2证据频率范围 | 250～3400 Hz |

IMCRA对7个物理麦分别维护噪声功率谱和语音存在概率`SPP`。v1.4.1已经删除旧的逐频7×7长期空间噪声协方差，不包含DPD或IMCRA Whitening。

每个麦克风的P1按三段频率聚合：

| P1证据频段 | 权重 |
|---|---:|
| 250～700 Hz | 15% |
| 700～1600 Hz | 35% |
| 1600～3400 Hz | 50% |

```text
单麦P1 = 0.15 × mean(SPP250-700)
       + 0.35 × mean(SPP700-1600)
       + 0.50 × mean(SPP1600-3400)

阵列P2 = 7个物理麦P1的中位数
```

P2表示当前20 ms内存在符合IMCRA语音频谱特征的声源证据。它不是响度，也不能单独证明某个具体人物正在讲话。

### 4.3 可选预降噪

IMCRA-Wiener预降噪默认关闭。开启后使用1920 sample分析帧、960 sample步长、2048点FFT和50%重叠的平方根Hann窗；最低增益为-18 dB。7个物理麦分别使用自己的IMCRA状态，HardwareMix保持不变。

## 5. L2：Gate、Norm-MUSIC和方向ID

### 5.1 P2 Gate

Gate默认阈值为`0.80`，并采用包含等号的判断：

- `P2 ≥ 0.80`：Gate OPEN，允许MUSIC扫描；
- `P2 < 0.80`：Gate CLOSED，不执行完整MUSIC扫描；
- IMCRA预热或概率不可用时，不输出正式Gate判断。

Gate只读取与当前DOA窗口末端严格对齐的最新20 ms P2。之前一个20 ms概率只作为诊断信息，不参与平均。

### 5.2 Norm-MUSIC

| 参数 | v1.4.1值 |
|---|---:|
| 输入 | 7路校准物理麦音频 |
| 滚动协方差上下文 | 200 ms |
| STFT窗 / 步长 | 20 ms / 10 ms |
| FFT长度 | 1024 |
| 定位频率 | 2000～4000 Hz |
| 扫描角度 | 0～359°，步长1° |
| 协方差收缩 | 0.05 |
| 对角加载 | 0.001 |
| 候选最低分数 | 0.35 |
| 峰值prominence | 0.05 |
| 最小候选间隔 | 50° |
| 最大候选数 | 3 |
| 默认有效阶数 | 2，可在UI选择1/2/3 |

每个频率点的360°MUSIC谱先单独归一化，再按阵列几何和频率权重融合。2～4 kHz是当前4 cm小孔径阵列在人声方向信息与高频混叠风险之间采用的工程折中。低频声源提供的麦间相位差较小，不适合直接作为主要定位证据。

Gate连续开启达到一个完整MUSIC上下文前，MUSIC响应只用于诊断，不允许新建方向ID。默认200 ms上下文对应连续10个20 ms hop。

### 5.3 Circular IMM-JPDA方向跟踪

| 参数 | v1.4.1值 |
|---|---:|
| 关联角度硬门限 | 50° |
| 最大建模角速度 | 60°/s |
| 新轨迹确认 | 500 ms内至少10次观测 |
| tentative有效期 | 500 ms |
| confirmed轨迹无观测预测 | 最长2000 ms |
| 内部最大活跃轨迹数 | 4 |
| 公共最大方向数 | 3 |

IMM同时维护“基本静止”和“缓慢移动”模型。JPDA在多个轨迹和候选之间进行概率关联。轨迹状态包括`tentative`、`confirmed`和`coasting`；`coasting`表示暂时没有新观测、当前角度来自预测。

`track_id`只保证同一次采集session中的空间轨迹连续性，不是声纹身份，也不能跨session代表同一个人。

## 6. Runtime、缓存和自适应回退

- L2使用容量100的有界队列，溢出策略为丢弃最旧窗口；
- UI邮箱只保留最新状态，避免慢界面反向阻塞采集；
- 音频只在内存保存最近500个20 ms块，即10秒；不写WAV；
- `tmp/l2_track_history.txt`只保存稀疏方向轨迹和ID持续时间；
- 性能监控只保留最近1秒事件，不累积历史；
- CDC热力图兼容缓存只保留最新1帧，避免50 Hz对象持续堆积。

正常情况下，L2每20 ms实算一次。当排队时间或IMCRA、概率、MUSIC、ID、L2总耗时中的任一项超过20 ms时，实算周期按20 ms逐级提高，最高200 ms。未实算的窗口沿用最近一次有效结果，但以当前窗口ID和sample时间继续发布，因此对外时间轴仍为20 ms。负载连续稳定低于12 ms达到5秒后，实算周期逐级恢复。

## 7. Development Test UI使用方法

首次创建专用环境：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup_vscode_env.ps1
```

启动界面：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\launch_dev_test_ui.ps1
```

使用步骤：

1. 连接Sipeed MA-USB8和阵列，确认Windows WDM-KS能够提供48 kHz、8通道输入。
2. 启动Development Test UI，点击“启动采集”。
3. 等待IMCRA完成约1秒预热。
4. 在L1区域观察8通道电平、7个P1和阵列P2；可按需打开IMCRA预降噪。
5. 在L2区域观察Gate状态、候选方向和方向ID；可调整Gate阈值、候选阈值和MUSIC阶数。
6. 右侧360°图显示MUSIC响应以及当前观测或预测方向。
7. 底部性能栏每秒显示IMCRA、P2、MUSIC、ID、总耗时、输出/实算帧率、队列、回退周期和故障数。
8. 完成后点击“停止采集”，再关闭程序。

v1.4.1只接受真实麦克风输入，没有模拟回放、正式录音或L3～L6处理入口。

- 真实采集、L1、L2、UI和自适应回退能够连续运行一小时；

本次长测不能支持以下结论：

- 不能证明MUSIC角度误差达到某个精度；
- 不能证明647个历史ID都对应真实讲话人；
- 不能证明双声源召回率、误报率或ID切换率已经合格；
- 不能代替带人工角度和讲话人真值的受控声场测试。

## 9. 当前限制

- 4 cm阵列在低频缺少足够空间相位差，不能可靠定位或分离低频声源；
- 近场声源、明显不共面声源和强混响会破坏二维远场模型；
- 两个候选方向小于50°时会受到NMS和阵列分辨能力限制；
- P2描述类似语音的声源证据，不是响度，也不是语义级人声识别；
- v1.4.1不保存音频，不能用于正式诊室录音；
- 当前长测显示ID出生规则仍需结合带标注数据继续收紧和验证。
