# 06 当前局限与待验证问题

本文属于**解释 + 验收边界**。用户原架构把本章预留为空；开始正式写作后，为避免开发者误把自动测试和历史长测理解为算法准确率验收，这里先补充代码能够确认的限制。后续可继续加入现场观察。

## 1. 当前功能范围

v1.4.3只包含：

- 真实8通道采集；
- 7物理麦校准；
- IMCRA、P1/P2和可选预降噪；
- GCC-PHAT突出方向数0/1/2；
- P Gate、NormMUSIC和方向取峰；
- Circular IMM-JPDA方向ID；
- Development Test UI、性能统计和稀疏轨迹日志。

当前`v1.4.3`分支不运行正式录音、回放、L3波束形成、L4双人分离、L5 NVIDIA人声CNN、L6声纹与人物身份、旧模型推理、HTTP服务或Production UI。上述完整功能及其代码、模型接口和历史说明均保存在不可变标签`v1.3.6`；需要查看或恢复旧完整系统时应从该标签检出。`v1.4.3`继续保持只含L1/L2的精简运行边界。

## 2. 物理模型限制

### 2.1 只估计二维方位角

系统没有俯仰角和距离输出。明显高于/低于阵列平面的声源会破坏二维导向模型。

### 2.2 远场平面波

近距离声源的球面波、幅度差和复杂安装结构没有进入模型。当前实现没有近场距离搜索。

### 2.3 房间传播

导向矢量是自由场几何模型。强混响和早期反射可能产生与直达声不同的空间结构，形成伪峰、角度偏差或重复ID。

### 2.4 阵列孔径

外圈半径4 cm、最大孔径8 cm。低频麦间相位差很小；接近4 kHz后又逐渐接近有限空间采样和阵列模型误差风险。当前2–4 kHz频带不能保证所有声源类型均可定位。

### 2.5 空间可分度图

![6+1阵列空间可分度图](assets/rho_map_100Hz_100_6000Hz_angle1deg.png)

- 横轴是频率，纵轴是两个声源的夹角。
- **绿色表示两个方向的空间特征差异较大，阵列较容易分开。**
- **红色表示两个方向很相似，阵列较难分开。**
- 图中的`rho`是两个方向的相似度：越接近0越容易区分，越接近1越难区分。

图中低频和小夹角区域大多偏红；进入2–4 kHz、且两个声源夹角增大后，绿色区域明显增加。这是当前DOA主要选择2–4 kHz，并要求双源至少相隔50°的原因。50°是当前取峰与追踪使用的最小分离边界，不代表达到该夹角就能稳定分开。

### 2.6 入射方向的影响

外圈只有6个离散麦克风。即使两个声源夹角相同，它们一起绕阵列旋转时，实际可分性也可能略有变化。因此这张图用于说明总体趋势，不保证每个绝对入射方向都得到完全相同的结果。

完整旧系统`v1.3.6`保存了按绝对入射方向展开的预计算空间可分度表：`spatial_separability/spatial_separability_p.npy`。表轴为`[frequency, theta-A mod 60°, signed delta]`，覆盖169个80–8000 Hz频率bin、60个第一声源绝对方向和360个有符号夹角，shape为`[169,60,360]`；生成程序是`v1.3.6:scripts/generate_spatial_separability_p_table.py`。当前热力图用于解释总体趋势，若需要逐频率、逐绝对方向的完整数值，应检出`v1.3.6`读取该表。

### 2.7 半波长与频带上限

相邻外圈麦间距为4 cm。经典半波长条件给出：

```text
f_half = c / (2d) = 343 / 0.08 ≈ 4.29 kHz
```

低频时半波长远大于4 cm，麦间相位差小，DOA和双人波束形成都缺少空间信息；接近4.29 kHz后相邻阵元接近半波长，再继续升频会增加空间混叠和阵列误差敏感性。2–4 kHz是低频不可分与高频风险之间的工程区间。

## 3. 通道定义仍需硬件复核

当前配置把native CH7映射为Center、CH6映射为HardwareMix。项目归档的MA-USB8官方资料把CH7描述为保留PEC通道。现有实机校准和项目测试以当前映射为契约，但更换固件、USB板或阵列时必须重新执行逐通道物理核验。

这是硬件事实核验项，自动测试只能证明“代码始终按当前映射执行”。

## 4. P Gate限制

- P2是加权SPP中位数，不是响度；
- 它使用人声宽带先验，但没有语义分类；
- 宽带方向性噪声仍可打开Gate；
- 窄带讲话、低SNR弱语音或频谱受损语音可能打不开Gate；
- 默认0.80和频段权重来自工程设计及有限环境统计，没有完成目标诊室ROC标定。

## 5. 声源数估计限制

GCC-PHAT计数器估计“可分辨的突出方向数”，不估计人数：

- 两个同方向或小于50°的源通常计为1；
- 第二源过弱、非宽带、相干或被反射覆盖时可能漏检；
- 主峰残差、共存帧和2-of-3阈值是工程初值；
- 讲话、扬声器、敲击等方向性声音采用相同规则；
- 当前自动测试主要使用合成自由场方向噪声；
- `tests/fixtures/audio/manifest.json`当前没有已登记真实回归音频。

真实0/1/2准确率、第二弱源召回和误报率尚未完成带标签标定。

## 6. MUSIC限制

### 6.1 阶数依赖

错误阶数会改变信号/噪声子空间。当前GCC-PHAT计数降低了自由阶数估计风险，仍可能把错误计数映射到MUSIC。

### 6.2 归一化必然产生最大峰

NormMUSIC把每个频率的最大值归一到1，再把最终空间谱归一到`[0,1]`。低能量或噪声协方差也会产生最大方向，必须由P Gate、持续活动和追踪生命周期共同过滤。

### 6.3 50°硬间距

任何两个候选小于50°都不能同时公开。真实50°边界源因测量误差收缩到49°时也会被抑制。

### 6.4 平面自由场阵列流形

麦克风坐标误差、频率响应、通道延迟、温度造成的声速变化和混响都会破坏正交关系。当前只有增益、极性和整数sample校准，没有分数延迟或频率相关复数校准。

### 6.5 不能判断声音类别

MUSIC只输出方向。即使Gate使用类似人声频谱证据，结果仍不能标注为“说话人方向”。

## 7. ID追踪限制

- ID是方向轨迹，不是人物身份；
- 两人交叉或先后占据接近方向时存在ID交换/继承风险；
- 两秒coasting保留的是方向假设，不能证明人物仍在场；
- 突然高速移动超过60°/s或超出50°关联门会新建ID；
- 救援关联提高连续性，也可能把50°范围内的新真实源吸收到旧轨迹；
- 重复合并依赖交替观测启发式；
- 参数尚未在带人物/角度真值的目标场景上系统优化。

## 8. 时间和延迟

- 新session的IMCRA需要约1 s预热；
- WindowAssembler首次需要160 ms音频；
- 新ID要求Gate连续OPEN 200 ms后才允许出生；
- tentative再需累计10次真实观测和存在概率门槛才confirmed；
- 预降噪一旦进入延迟链会引入块级缓冲关系；
- 自适应周期升高时确认时间窗相应延长。

因此“20 ms更新”表示稳态决策步长，不表示启动后20 ms即可得到成熟confirmed ID。

当前实机观察从声音出现到界面形成稳定识别约有700 ms延迟。它包含P2建立、Gate连续OPEN约200 ms、声源数稳定投票、MUSIC/ID出生和UI刷新等环节，具体值会随Gate、信号强度、自适应周期和confirmed口径变化。后续若需要补全讲话开头，可在内存中保留有界回溯音频，并在方向ID稳定后按绝对sample回溯处理；回溯不得跨session/epoch或把未确认方向静默写成正式ID音频。

## 9. 实时性限制

项目通过单线程OpenBLAS/OMP、小矩阵批处理、有界队列和动态回退控制抖动。实时性仍取决于：

- CPU、Python/NumPy/SciPy版本；
- Windows音频驱动和调度；
- Gate开启比例；
- 同时活动轨迹数量；
- 是否开启预降噪；
- 其他进程负载。

队列容量只保证内存有界。采集handoff或L2队列溢出会丢弃旧块/旧窗并建立健康事件或计数`processing_drops`，不能恢复丢失音频。

## 10. 缓存和持久化边界

- Runtime逻辑音频环只保留最近1 s；
- AudioCapture底层原始块环只保留约1 s；
- UI邮箱容量1，只保留最新状态；
- 性能事件只保留最近1 s；
- 轨迹日志异步写`tmp/l2_track_history.txt`，最多64个历史ID、每ID 240个约5 s间隔轨迹点；
- 不写WAV；
- `data/`、`tmp/`和日志不进入Git。

轨迹日志写入失败只进入诊断，不会停止L2。它不是完整审计记录，也不能用于还原音频。

## 11. 预降噪限制

IMCRA-Wiener预降噪默认关闭。逐麦时频增益可能改变跨麦协方差和弱第二源能量；项目尚无带真值实机A/B证明其对DOA有利。开启后必须重新评价Gate、计数、MUSIC和角度。

## 12. 自动测试能证明什么

当前160项测试覆盖：

- shape、dtype、不可变性和身份对齐；
- 通道映射、校准和HardwareMix隔离；
- IMCRA公式状态和Gate权重；
- 断流、epoch和有界队列；
- 合成0/1/2源、MUSIC方向和跨0°；
- JPDA、TTL、救援、合并和自适应复用；
- UI控件、布局和原子快照。

它们证明代码在构造场景下遵守契约。它们不能证明目标房间中的角度准确率、声源数准确率、人物ID连续性或主观音频质量。

## 13. v1.4.3一小时实机测试

用户完成的v1.4.3实机1小时测试结果为：

- 系统保持实时；
- 运行稳定；
- 未观察到内存泄漏；
- 进程内存占用约200 MB。

该结果用于当前版本的运行稳定性说明。它不等同于角度、双源召回率、声源数或人物ID准确率测试。

## 14. v1.4.1一小时长测的适用边界

用户提供的v1.4.1参考PDF记录了3600.5 s真实麦克风稳定性测试。该报告可证明当时版本的线程、队列、UI和自适应机制能够长时运行，不能直接当作v1.4.3准确率或当前资源占用证据。

从v1.4.1到v1.4.3已发生的重要变化包括：

- IMCRA升级为960点FFT和v11频段权重；
- 音频环从历史10 s收紧到当前1 s；
- 加入持续GCC-PHAT声源数及阶数跟随；
- L2与声源数改为同窗原子快照；
- 自适应预算、ID确认窗、UI显示和跟踪规则有修复。

PDF中的数值必须标明“v1.4.1历史结果”，不能改写为v1.4.3已验收结果。

## 15. 当前缺少的实机验收

建议后续建立带元数据的受控测试集：

1. 静音、风扇、HVAC、键盘、敲击和宽带噪声；
2. 单人语音全角、不同距离和高度；
3. 双人50/60/90/120/180°；
4. 第二源相对强源0/3/6/10/15 dB；
5. 不同SNR、RT60和声速；
6. 短时静音、漏检、交叉和移动；
7. 预降噪开关A/B；
8. 20–200 ms自适应周期；
9. 至少1小时和更长稳定性；
10. 明确角度、人数和真实讲话人标签。

至少报告：Gate误开/漏开、计数混淆矩阵、角度MAE、双源全解析率、false births/min、ID switch、确认延迟、P95/P99耗时、drop和内存斜率。
