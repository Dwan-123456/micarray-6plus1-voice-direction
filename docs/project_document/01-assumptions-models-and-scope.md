# 01 基本假设、模型与适用范围

本文属于**原理解释 + 技术参考**。目标读者能够阅读Python和配置文件，但不要求预先掌握阵列信号处理。

## 1. v1.4.3解决什么问题

v1.4.3接收Sipeed MA-USB8提供的实时8通道音频，使用其中7路项目定义的物理麦克风完成三件事：

1. 每20 ms估计环境噪声和声源存在概率；
2. 判断当前可分辨的突出方向声源数为0、1或2；
3. 在Gate开启时估计声源方位角，并把连续观测关联成方向`track_id`。

系统输出的是**空间方向轨迹**。它不输出距离、俯仰角、语音文字、说话人身份或分离后的讲话音频。

## 2. 从单麦声音到阵列方向

单个麦克风只能记录声压随时间的变化。多个位置不同的麦克风接收到同一远处声波时，波形之间存在微小到达时间差。已知麦克风坐标和声速后，可以比较这些相位差或时延，判断哪个方向最符合实际观测。

对位于平面坐标`r_m = [x_m, y_m]`的第`m`个麦克风，来自方位角`theta`的二维远场平面波可写成方向单位向量：

```text
u(theta) = [cos(theta), sin(theta)]
```

项目采用的相对到达延迟为：

```text
tau_m(theta) = -(r_m · u(theta)) / c
```

其中`c=343 m/s`。频率为`f`时，相应的复数导向项为：

```text
a_m(f, theta) = exp(-j 2 pi f tau_m(theta))
```

`a(f, theta)`把一个候选方向转换为7个麦克风应呈现的相位关系。GCC-PHAT和MUSIC都以这个物理关系为基础，但使用方式不同：GCC-PHAT直接比较麦克风对时延，MUSIC比较候选导向矢量与协方差子空间的正交关系。

## 3. 二维远场平面波假设

### 3.1 二维

程序只扫描水平面`0..359°`，不扫描俯仰角。真实声源若明显高于或低于阵列平面，同一个三维方向可能被投影成不准确的水平角。

### 3.2 远场

远场假设认为同一声波到达整个8 cm孔径时近似为平面波。近场声源的波前更接近球面，各麦克风的幅度和时延同时受距离影响，当前自由场平面导向矢量无法完整描述它。

### 3.3 自由场导向模型

当前导向矢量只使用麦克风几何、声速、频率和方向。房间反射、桌面反射、麦克风频率响应误差和安装结构没有进入导向模型。这些因素会使真实阵列流形偏离理论值。

## 4. 方位角坐标系

观察方向为从LED面向下看阵列：

- 阵列中心是原点；
- Center到MIC0方向是`+x`和`0°`；
- 正角度逆时针增加；
- 外圈物理麦角度依次为MIC0=`0°`、MIC1=`300°`、MIC2=`240°`、MIC3=`180°`、MIC4=`120°`、MIC5=`60°`；
- Center位于`[0,0]`。

圆周角度不能使用普通减法。例如`359°`与`1°`相差`2°`，程序使用：

```text
delta = ((theta - reference + 180) mod 360) - 180
```

所有方向归一化到`[0,360)`。

## 5. 固定采样与时间尺度

| 项目 | v1.4.3固定值 | 含义 |
| --- | ---: | --- |
| 采样率 | 48,000 Hz | 每通道每秒48,000个样本 |
| 设备块 | 960 samples | 20 ms采集块 |
| 决策步长 | 960 samples | 每20 ms产生一个新决策时刻 |
| DOA边界 | 1,920 samples | DTO中记录的最近40 ms边界 |
| `DecisionWindow` | 7,680 samples | 每个公开窗口携带160 ms、8通道音频 |
| 声源数上下文 | 160 ms | 15个20/10 ms重叠STFT帧 |
| MUSIC目标历史 | 200 ms | 初始160 ms，连续更新后扩展到19个STFT帧 |
| IMCRA预热 | 1 s | 新session或校准变化后建立噪声统计 |
| UI输出时钟 | 20 ms | 正常约50次/s |

需要区分“单个DTO携带的音频长度”和“算法跨窗口保存的递归状态”。`DecisionWindow`只有160 ms；MUSIC扫描器把前一窗口的协方差帧保存在内存中，连续两个20 ms更新后达到完整200 ms滚动历史。

## 6. 0、1、2个突出方向声源

声源数估计器输出`0/1/2`，含义是当前阵列在2–4 kHz中能够分辨的**突出方向成分数量**：

- `0`：能量或空间集中度不足；
- `1`：存在一个可靠主方向；
- `2`：存在两个相距至少50°、在多个STFT帧中同时得到支持的方向。

它不判断声音类别。讲话、扬声器、敲击和其他方向性噪声都可能被计数。两个真实声源若方向过近、频带能量不足或第二源明显较弱，仍可能只得到`1`。

## 7. P Gate与声源数的职责不同

P Gate使用IMCRA产生的P2，尝试回答“当前20 ms是否存在足够宽带、类似人声频谱的声源证据”。声源数估计使用GCC-PHAT，回答“当前160 ms空间图中有几个可分辨的突出方向”。

因此：

- Gate关闭时，声源数估计默认仍继续运行；
- Gate只决定是否执行MUSIC；
- Gate不能证明声音一定是人声；
- 声源数也不能证明每个方向对应一个人。

## 8. 方向数量和角度分辨边界

MUSIC配置允许最多3个候选，但v1.4.3运行时只使用1阶或2阶MUSIC，所以正常公开观测最多为2个方向。方向候选使用50°硬圆周间距；小于50°的两个峰不能同时成为公开候选。

4 cm半径、8 cm最大孔径决定了低频空间相位差很小。当前2–4 kHz定位频带是空间分辨力、语音能量和约4.1–4.3 kHz空间采样上界之间的折中。

## 9. 适用场景

当前实现适合：

- Windows主机连接当前MA-USB8与6+1阵列；
- 48 kHz、同步8通道实时输入；
- 室内相对稳定、以水平远场方向为主的声场；
- 同时0–2个突出方向源；
- 两个方向至少相隔约50°；
- 只需要实时方向、轨迹状态和诊断信息。

当前50°是算法硬下限附近的压力边界。工程布置推荐尽量让两个同时讲话方向相隔约90°或更大，以给阵列孔径、混响、DOA误差和50°NMS留出余量。

系统依赖宽频带方向证据。纯音调、频带很窄或大部分2–4 kHz能量缺失的声源不属于优先目标；人声也应尽量与阵列处于相近高度，使其主要传播方向接近阵列平面。

## 10. 模型外场景

以下场景需要额外算法或重新标定：

- 近距离声源或明显俯仰角；
- 强混响、强镜面反射或阵列附近遮挡；
- 两源夹角小于50°；
- 三个及以上同时突出方向；
- 把方向ID当成人物ID；
- 需要正式录音、语音分离、声纹或语音识别；
- 更换麦克风数量、几何尺寸、通道顺序或采集硬件。

## 11. 身份和连续性边界

`session_id`标识一次Runtime采集生命周期，`stream_epoch`标识该session内一段连续sample时间轴。断流、丢块、时间戳异常、设备健康事件或校准身份变化会建立新epoch。输入采样率若不是固定48 kHz，Coordinator会直接拒绝并报告处理错误，不建立新epoch继续处理。

`track_id`只在一个session内标识方向轨迹。epoch变化会清空活动轨迹，但同一session中的ID计数保持单调；显式关闭ID追踪会安排一次完整ID重置。任何情况下都不能把`track_id`解释为说话人的生物身份。

## 12. 版本范围

本文只描述`codex/develop-v1.4.3`当前代码。完整L1–L6、录音、模型和旧Production UI保存在不可变标签`v1.3.6`。归档文档中的参数可能属于v1.3.6、v1.4.1或中间实验，不可覆盖当前代码和`config/config.yaml`。
